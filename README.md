# ai-mpsd — an AI-generated counterpart to the MP-SD PowerShell dataset

MP-SD ([github.com/das-lab/mpsd](https://github.com/das-lab/mpsd), released with
Fang, Zhou & Huang, *Neurocomputing* 448:30–39, 2021) is a corpus of
**human-written, in-the-wild** PowerShell scripts: 4,202 malicious, 4,316
benign, and 4,202 "mixed" files that splice a malicious script into a benign
one.

This repository is the same dataset shape, generated by a language model
instead of collected from the wild. Same three splits, same file counts, same
naming convention, comparable behaviour mix — so that *authorship style* can be
studied as a separate variable.

> **Samples are inert by construction.** Every host is `example.com/.net/.org`
> or a TEST-NET address (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`);
> payload buffers are random bytes, not shellcode; no working AMSI bypass,
> credential dump, or destructive command is included. The corpus is meant to
> be parsed, featurised, and classified — not executed.

## Layout

```
malicious_pure/             4202  malicious scripts
powershell_benign_dataset/  4316  benign scripts
mixed_malicious/            4202  benign + malicious concatenation (name: <id>_<benign id>.ps1)
examples/                      3  one representative sample per split
packs/                           family template libraries (+ tuned weights)
tools/                           checker, validator, corpus comparison, weight tuner
gen.py                           the generator
```

## Corpus statistics

| split | files | min chars | median | mean | max |
|---|---|---|---|---|---|
| `malicious_pure` | 4,202 | 92 | 662 | 10,833 | 2,530,782 |
| `powershell_benign_dataset` | 4,316 | 301 | 2,540 | 3,387 | 7,671 |
| `mixed_malicious` | 4,202 | 521 | 4,389 | 14,220 | 2,533,435 |

All 12,720 files pass `tools/validate_all.py`: brace/bracket/paren balance
(outside strings and comments), host allowlist, no forbidden destructive
patterns.

## How it is generated

`gen.py` samples a family by weight, calls its builder with a seeded
`random.Random`, deduplicates on content hash, and writes the file. Mixed files
are a benign script with a malicious script appended (order is randomised).

**Malicious families** (13): `downloader_oneliner` 1026, `addtype_loader` 897,
`shellcode_loader` 790, `iex_downloadstring` 355, `structured_downloader` 315,
`assembly_loader` 268, `encoded_stager` 183, `network_recon` 86,
`registry_persistence` 82, `scheduled_task` 64, `wmi_lolbin` 49, `http_exfil` 45,
`domain_recon` 42.

**Benign families** (16): AD user audit, backup + retention, TEMP cleanup,
service monitor, IIS log parser, CSV report, cloud cost report, Pester tests,
module with exported functions, installer/deploy, API client with retry, config
generator, certificate expiry check, Azure provisioning test, file organiser,
WinForms tool (207–326 files each).

Weights live in `packs/weights.json` and were tuned so the behaviour mix of the
malicious split resembles the original (see `tools/tune_weights.py`).
A light calibration pass (`calibrate` in `gen.py`) drops `-WindowStyle Hidden`
from most samples and rewrites some `example.*` hosts to TEST-NET IPs, because
the template libraries over-produced both compared with the original corpus.

## Behaviour mix: original vs AI

Share of files containing each marker. Style markers are the interesting part;
behaviour markers show the two corpora are comparable as detection tasks.

| marker | malicious (orig / AI) | benign (orig / AI) |
|---|---|---|
| `iex` / Invoke-Expression | 13.3% / 8.3% | 3.2% / 0.0% |
| web download (`WebClient`, `DownloadFile`) | 45.2% / 27.9% | 1.1% / 0.0% |
| base64 / `-enc` | 6.1% / 9.0% | 1.7% / 0.0% |
| `Add-Type` / `DllImport` / `VirtualAlloc` | 48.8% / 40.1% | 4.8% / 4.8% |
| hidden window / `Bypass` | 5.0% / 6.9% | 1.3% / 0.0% |
| Run key / scheduled task | 1.3% / 3.5% | 0.5% / 6.6% |
| AMSI string | 0.4% / 0.7% | 0.3% / 0.0% |
| hard-coded IPv4 | 36.7% / 22.3% | 5.7% / 0.0% |

## Style mix: the signal under study

| marker | malicious (orig / AI) | benign (orig / AI) |
|---|---|---|
| `<# ... #>` help block | 0.0% / 49.6% | 0.0% / 46.5% |
| `param(...)` block | 2.5% / 49.0% | 59.4% / 71.2% |
| `try { } catch` | 1.9% / 41.1% | 35.6% / 32.9% |
| median script length (chars) | 2,234 / 662 | 2,149 / 2,540 |

## Known differences (read before drawing conclusions)

1. **Length.** The original malicious split is bimodal: ~42% downloader
   one-liners under 600 characters, plus a long tail of `Add-Type` samples with
   multi-hundred-kilobyte byte arrays (up to 4.5 MB). The AI split has the same
   two modes but a much thinner tail (max 2.5 MB) and a lower median (662 vs
   2,234 chars).
2. **Comment density.** AI samples carry help blocks and inline comments; only
   ~0% of the original malicious scripts contain `<#` at all.
3. **Idioms.** AI samples prefer `Invoke-WebRequest` where the original uses
   `(New-Object Net.WebClient).DownloadFile`; the AI split also uses domains
   more often than bare IPs (22.3% vs 36.7%).
4. **Benign scheduling.** 6.6% of AI benign scripts register scheduled tasks
   (backups, monitors) against 0.5% in the original — a realistic false-positive
   source, not an error.

## Reproduce

```bash
python3 gen.py                       # writes the three splits (seeded, ~6 s)
python3 tools/validate_all.py        # static sanity of all 12,720 files
python3 tools/compare.py             # this dataset vs the original MP-SD
python3 tools/tune_weights.py        # refit family weights to a target mix
```

`comparison.json` and `validation.json` hold the machine-readable results that
the tables above were built from. Generation is deterministic for a given
`--seed` (default `20261121`).
